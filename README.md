# 💡 IdeaBox

**Корпоративная платформа для сбора, модерации и сопровождения инициатив сотрудников.**

IdeaBox позволяет сотрудникам предлагать идеи по улучшению внутренних процессов, прикладывать необходимые материалы и отслеживать дальнейшее рассмотрение инициатив. Модераторы получают отдельную панель управления для обработки предложений, изменения статусов, публикации идей и анализа статистики.

Проект разработан как внутреннее веб-приложение и поддерживает контейнеризованное развёртывание через Docker.

## Возможности

### Для сотрудников

- создание новых идей и предложений;
- описание проблемы и предлагаемого решения;
- выбор категории инициативы;
- прикрепление файлов;
- публикация одобренных идей;
- получение email-подтверждения после отправки;
- получение уведомлений при изменении статуса идеи.

### Для модераторов

- отдельная авторизация;
- панель управления поступившими идеями;
- фильтрация по категории, статусу и публикации;
- сортировка и пагинация;
- редактирование инициатив;
- изменение статусов;
- публикация и снятие идей с публикации;
- обратная связь автору;
- управление категориями;
- просмотр статистики;
- экспорт данных в Excel.

## Жизненный цикл идеи

Инициатива может проходить несколько этапов:

`На рассмотрении → Одобрено → На реализации → Реализовано`

Также поддерживаются статусы:

- одобрено частично;
- отклонено.

## Архитектура

Приложение построено с использованием Flask Application Factory и разделено на несколько Blueprints:

```text
app/
├── blueprints/
│   ├── auth.py          # авторизация модераторов
│   ├── ideas.py         # создание идей и работа с вложениями
│   ├── moderator.py     # административная панель
│   └── public.py        # публичная часть приложения
│
├── models.py            # модели SQLAlchemy
├── forms.py             # формы и валидация
├── notifications.py     # email-уведомления
├── extensions.py        # Flask extensions
├── template_utils.py
├── templates/
└── static/
```

Точка создания приложения:

```text
create_app()
   │
   ├── configuration
   ├── SQLAlchemy
   ├── CSRF protection
   │
   └── Blueprints
       ├── public
       ├── auth
       ├── ideas
       └── moderator
```

Такое разделение позволяет не хранить всю бизнес-логику и HTTP-маршруты в одном файле и упрощает развитие приложения.

## Модели данных

Основные сущности приложения:

### Idea

Хранит информацию об инициативе:

- заголовок;
- описание проблемы;
- предлагаемое решение;
- автор;
- контактный email;
- категория;
- статус;
- обратная связь модератора;
- дата создания;
- состояние публикации.

### Attachment

Файлы, прикреплённые к инициативам.

### Moderator

Учётные записи сотрудников, имеющих доступ к панели модерации.

Пароли модераторов хранятся в виде хэшей.

### IdeaCategory

Категории инициатив с возможностью включения и отключения.

## Безопасность

В приложении используются:

- CSRF-защита форм;
- серверная проверка загружаемых файлов;
- хэширование паролей;
- защищённые session cookies в production-конфигурации;
- разделение публичных и административных маршрутов;
- хранение конфигурации и секретов в переменных окружения.

## Конфигурация

Приложение использует `.env` для конфиденциальных параметров.

Пример:

```env
SECRET_KEY=your-secret-key

SQLALCHEMY_DATABASE_URI=sqlite:///ideas.db

SMTP_SERVER=smtp.example.com
SMTP_PORT=587
FROM_EMAIL=example@example.com
EMAIL_PASSWORD=your-password
MODERATOR_EMAIL=moderator@example.com

MODERATOR_VLASUK_PWD=change-me
MODERATOR_SCHEKOLDINA_PWD=change-me
```

Файл `.env` не должен добавляться в Git.

## Запуск через Docker

Клонировать репозиторий:

```bash
git clone https://github.com/romatimon/ideabox.git
cd ideabox
```

Создать `.env` с необходимыми переменными окружения.

Собрать и запустить контейнер:

```bash
docker compose up -d --build
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:5000
```

Для загружаемых файлов и базы данных используются отдельные Docker volumes, поэтому данные сохраняются между перезапусками контейнера.

## Локальный запуск

Создать виртуальное окружение:

```bash
python -m venv venv
```

Активировать его и установить зависимости:

```bash
pip install -r requirements.txt
```

Создать `.env`, после чего запустить приложение:

```bash
python run.py
```
